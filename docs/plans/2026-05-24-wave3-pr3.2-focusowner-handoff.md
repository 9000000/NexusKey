Anh's design tenets — every refactor decision must justify itself against these:

### Core tenets
1. **Nhanh / gọn / nhẹ / mượt / plugin** — five-word product spec. Latency budgets are real (Tier-2 p99 = 30 ms; hard ceiling 100 ms). Memory footprint matters. UI feels instant.

### Cross-platform pitfalls (PR 3.1 lessons — apply to PR 3.2+)
1. **Linux build doesn't catch MSVC warning-as-error.** `std::filesystem::u8path` is C++20-deprecated, MSVC C4996 fails. Use conditional construction:

**Why this split is "đúng triết lý":**
- HookEngine = thin coordinator. Apply* are handlers — they belong in the orchestrator.
- FocusOwner = "ai đang focus + classify it". Single concern.
- PR 3.5 cleanup will NOT need to move Apply* again — they're already in their END location.
- Mirrors PR 3.1 pattern: 1 callback (drainFn), HookEngine reads from owner. **NOT** 5-callback inverse-god.

**Why NOT Option B** (move Apply* into FocusOwner): would require 5 callbacks pushed into FocusOwner (composition-reset, mode-set, injector-publish, autocap-reset, engine-recreate). FocusOwner becomes a focus-god ràng buộc 5 subsystem. Phân mảnh in inverse direction.

**Why NOT Option C** (state only, no Classify): splits Classify from its state. Weak owner with no behaviour. Phân mảnh.

- **Main/worker single-thread** for `appProfileCache_` + `webView2PositiveCache_` — both via OnFocusChanged → Classify, serialized by Windows message loop. Don't add hook-thread Classify caller.
- **Hook thread single-writer** for `currentExe_` / `previousExe_` / `appModeMap_` / `appModeDirty_` / layout fields. Only `ApplyFocusOnHookThread`, `ApplyTickPollOnHookThread`, `OnLayoutChanged` touch these. The `VKEY_ASSERT_HOOK_THREAD()` macro at the top of each is the guardrail.
- **`cachedFocusedHwnd_` atomic write rule:** ApplyFocusOnHookThread (hook thread, `RefreshFocusCache` / `InvalidateFocusCache`) AND `LowLevelMouseProc` (mouse hook thread, `InvalidateFocusCache`). HWND is atomic; class wstring tuple race is benign.
- **`lastForegroundPid_` atomic ordering:** hook write (release) / worker read (acquire). FocusOwner getters/setters already use these orderings.
